# 目录、任务与记忆的边界

> 回答三个问题：办公室目录谁能写？多个产品能不能同用一套任务库？记忆会不会串？
> 结论：**可以共用一个账本，不能共用一个可写目录。**

## 1. 三类目录，三种角色

| 目录 | 例子 | 谁写 | 作用 |
|---|---|---|---|
| **代码仓** | `D:\aiCoding\projects\vibe-mission` | 开发者（人 / 该仓的 agent） | 源码，单一来源 |
| **项目执行目录** | `D:\shibei-memory-book` | 该项目任务的子会话 | 真正干活的地方，由 `projects.json` 决定 |
| **办公室** | `D:\vibemission-office` | 人 + 各产品自己的子目录 | 文档、日报、素材，不是执行区 |

关键：**办公室不是工作区。** 任务在项目目录里执行，办公室只放过程材料。

## 2. 多产品共用一个账本：可以，靠三件事

1. **`product` 字段**：每条任务标明属于哪个产品，看板可按产品筛。
2. **单一写者**：一个任务同一时刻只有**当前执行产品**能写状态；其他产品只读。换产品接手 = **显式转派**（改 `owner_product` + 写 `handoff` 事件），不是两边同时写。
3. **`session_id` 归属**：任务记录当前执行会话；派工只派给当前执行产品的会话，不跨产品并行派工。

违反其中任一条，就会出现"两个 agent 同时改一条任务、状态互相覆盖"——这是账本层面的混乱，比目录混乱更难查。

## 2.1 目录模型：办公室私有，任务共享

多产品（含多台云服务器上的产品）统一按下面这套落：

```
vibemission/
├── shared/                    所有产品可读
│   ├── ledger/tasks.sqlite    账本：唯一真相
│   └── tasks/                 任务过程稿与证据（跨产品交接也在这里）
└── offices/
    ├── zcode/                 该产品独占写：inbox / reports / 自己的草稿
    └── workbuddy/             同上
```

**为什么任务在 shared**：任务可能跨产品执行（ZCode 起手、WorkBuddy 接手），资产不能锁在某个产品的办公室里，否则接手方读不到。
**为什么办公室私有**：每个产品的日报、上下文、草稿互不污染；出问题时能用目录回答"这是谁写的"。

**跨产品执行的三条规则**

1. 转派必须留事件：`handoff` 写明从谁到谁、原因、当前进度与待办；
2. 同一时刻只有一个执行产品，另一个是"前手"或"后手"，不并行写状态；
3. 接手方读 `shared/tasks/` + 账本事件，不从自己办公室猜。

## 3. 多产品共用一个目录：不建议写入

**共用只读可以，共用写入不行。**

- `shared/`：所有 agent 可读；写由人来做，避免多方覆盖。
- `products/<id>/`：每个产品独占写。WorkBuddy 写 `products/workbuddy/`，ZCode 写 `products/zcode/`。
- 需要在同一目录协作时，走"人转述 + 文件版本"（谁写谁签名、文件名带日期），不并发写。

## 4. 记忆为什么会串，怎么防

记忆系统（如 ai-memory）通常按 **工作目录 + 会话** 归属：

| 情形 | 结果 |
|---|---|
| 两个产品同一个 cwd | 会话记录落到同一个项目下，时间线交错，检索时互相干扰 |
| 每个产品自己的 cwd | 各自成项目，互不污染；需要跨项目查询时显式指定 |
| 同一 cwd 但不同任务 | 仍在同一项目内，但靠会话 id 区分；不影响正确性，只影响阅读 |

**防串的三条**：

1. 每个产品用自己的执行目录（`projects.json` 里 `workspace` 各不相同）；
2. 办公室按产品分子目录；
3. 任务卡记 `project` + `workspace`，不靠"我记得它在哪"。

## 5. WorkBuddy 怎么接

- 适配器代码在 `adapters/workbuddy/`（同一仓库），安装到 WorkBuddy 侧指的是那份包；
- 它的**执行目录**由 WorkBuddy 项目在 `projects.json` 里的 `workspace` 决定，不是办公室；
- 它的**文档产出**写 `office/products/workbuddy/`；
- 它登记的任务进同一账本，`product: workbuddy`，ZCode 侧只读。

## 6. 一句话总结

**一个账本（按 product 分），各自目录（按 project 分），办公室只读为主（按 product 分子目录）。**
