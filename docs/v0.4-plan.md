## 1. 问题陈述（用账本事实说话）

实测（2026-11-27 12:00 前后，`task_list` 全量）：**38 条总账 = 7 done（evidence 均含 merged PR）+ 3 cancelled + 28 活跃**（13 `waiting_decision` / 14 `blocked` / 1 `todo`）。

真实问题不是"堆积"一件事，而是三件：

1. **无主**：`tasks` 没有 `owner` / `assignee` 字段（`core/src/store.mjs:15-29`），归属只能靠 `host` / `project` / `workspace` 隐式推断。无人认领的条目在账本上与有人负责的条目长得一样。
2. **混合语义**：28 条活跃里，4 条是会话中断待续、13 条是二选一、11 条是等外部（等 review / 等审批 / 等重启）。同一个 `blocked` / `waiting_decision` 状态承担三种不同语义，所以看起来"全都在堆"。
3. **断线**：运行期注入断（G1）、运行时 skill 陈旧（G2）、无入向收敛层（G4）。新任务只增不减，旧任务没人清。

对应措施：M5 清旧账解决 1、2 的存量；M1/M2 解决增量里的"关不掉也派不出去"；M6 解决 3 里最便宜的一条。

## 2. 分诊（M1）

### 2.1 判据：写死，只认证据

| 类别 | 判据（全部可查） | 证据来源 | 决策权 |
|---|---|---|---|
| **关** | ① 有 merged PR；② 有明确过期时间且已过；③ 与已有活跃任务重复（标题 + keywords 命中同一意图） | `evidence` 链接、`recheck_at`、重复检测结果 | 证据齐 → 账本校验 + 人确认后才关；**模型不得单独关** |
| **派** | 不需人拍板 **且** 执行者有能力承接（宿主在线、能力匹配、未超并发上限） | 任务类型 + `dispatch-gate.mjs --check` | 自动派，写 `dispatched` 事件 |
| **留** | ① 需资源 / 权限 / 对外承诺；② 选项间无客观优劣（商业取舍）；③ 判据自相冲突（既可关又可派） | 任务内容 + 人工判断 | 人拍板 |

模型输出 `{class, reason, evidence_ref, confidence}`，落 `triage_suggested` 事件；**不落库的结论不生效**。判据冲突（例如既有 merged PR 又被人要求续做）一律降级为"留"。

### 2.2 关闭契约（M2）

- 新增列 `close_reason TEXT`；`task_update` 迁到 `done` / `cancelled` **且** 分诊类别为"关"时，`close_reason` 与 `evidence` 缺一 → 拒绝，错误码 `CLOSE_EVIDENCE_REQUIRED`。
- 关闭事件 payload 固化 `{close_reason, evidence, triage_class}`，一周后仍可回溯"当初为什么关"。
- 现状反例：tp-0035 已是 `done`，`blocked_reason` 仍留着历史失败原因——说明缺独立字段，`blocked_reason` 会被复用成注释。字段落地依赖 [G6 迁移](implementation-gaps.md#g6-无-schema-迁移机制)，不能只写流程。

### 2.3 无主补法：`owner` + `recheck_at`

- 新增 `owner TEXT`（角色标识或人名，如 `zcode:owner`）+ `recheck_at INTEGER`（"等外部"类的复查时间戳）。
- 派工必须落到三选一之一：宿主会话 / 人 / 等外部（带 `recheck_at`）；三者都没有 → 不允许留在活跃态（创建时即拦）。
- 工具面：不加新工具，只给 `task_create` / `task_update` 加可选字段（D20-① 冻结的是工具数量，不是字段）。

## 3. 告警合并（M3）

**触发源是这版最大的新增工作量**：`notify.mjs` 目前只能手动跑，仓库里没有任何定时器（`grep -rn "notify.mjs"` → 只有文档与测试）。

| 方案 | 取舍 |
|---|---|
| **Windows 计划任务**（12:00 / 18:00 各一次，跑 `node channels/feishu/notify.mjs --digest`）**选此** | 不依赖宿主是否开着；代价=关机不跑，开机补一条"上次摘要以来的新增" |
| 宿主 Stop 钩子 + 时间闸门 | 少一个外部依赖，但宿主管不到时漏，且 Stop 触发频繁需冷却 |
| 常驻 daemon | 多养一个进程，崩溃无人看，与"轻"的定位冲突 |

合并规则：

- 按状态分组，每组一个头 + 逐条一行（`#N 标题 [状态] 一句原因`）；
- 同任务 10 分钟幂等**保留**，幂等在合并之下、不废止；
- 空批不推；单批超过 15 条只发头 + "其余 N 条见看板"；
- **紧急直通**：新进 `blocked` 且原因带明确"卡住不能动"标记 → 立即单发，不等窗口。

## 4. 高风险审批五类（M4）

合并 / 发布 / 删除 / 权限 / **批量修改数据**（批量导入、清理、迁移）。

判定口径写进 skill：动作作用对象 **超过 1 行数据**，或 **不可撤销**，或 **对外可见** → 走审批。其余默认自主（与 D22 一致）。
