# vibemission-owner 技能触发评估（v1 → v2）

> 方法限制：本机没有可用的真实 harness 评测器（skill-creator 的 run_eval 需要 claude-with-skill 环境），
> 这里做的是**描述匹配评估**——只看 SKILL.md 的 description 与用户原话，判断是否会被选中。
> 它验证"描述覆盖不覆盖触发词"，不等价于真实模型触发率；重启插件后应用真实对话复验。

## 修改点

v1 描述只有抽象词（任务管理/派工/跟踪/验收），漏掉了用户真实会说的**动词和名词**：

- 补触发词：记一下、派给谁、编号进展、卡住、通过/打回、停掉、谁在做什么
- 补排除项：纯代码评审、文案润色、知识问答——这些不该抢占这个技能

## 局限

- 这份评估由同一模型完成，"自己判自己"存在偏差；数字用于横向比较（v1 vs v2），不做绝对准确率。
- 真实触发受宿主如何拼接技能清单、描述截断策略影响，需重启后在飞书对话里复验。
